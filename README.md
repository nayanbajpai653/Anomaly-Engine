# Excel Anomaly Detection Agent

A local tool that finds anomalies in any Excel/CSV file and explains them in
plain business language. A small local web server (Flask) serves a plain
HTML/CSS/JS page in your browser, and you trigger it manually each time.
Nothing runs in the background or on a schedule, and nothing leaves your
machine unless you turn on the optional Ollama step.

## How it works

1. **You upload** an Excel or CSV file.
2. **It detects anomalies two ways** and combines them:
   - *Statistical*: Z-score and IQR on each numeric column.
   - *ML*: Isolation Forest across all numeric columns together (catches
     combinations that look odd even if no single column is extreme).
   - A row flagged by **both** gets "High" confidence; by **one**, "Medium."
   - **Auto mode** (default): all thresholds are derived from the data
     itself — nothing to configure. The Isolation Forest's expected-anomaly
     rate is set from how often the statistical method already flags this
     specific file, so it adapts per dataset instead of using one fixed guess.
   - **Manual mode**: flip the sidebar toggle to get the Z-score threshold,
     IQR multiplier, and anomaly-fraction sliders back, if you want to tune
     them yourself.
3. **High-risk category weighting** (optional): pick one categorical column
   (e.g. "Department" or "Vendor") and mark specific values as high-risk,
   once — it's saved in `config.yaml` and reused every time you run the app.
   Rows in those categories get their confidence boosted.
4. **Business-context notes**: each flagged row gets a short plain-English
   explanation, generated by a local Ollama model. If Ollama isn't running,
   the app automatically falls back to an offline, template-based note — it
   never blocks or crashes because of this.
5. **Output**: results shown as cards in the browser (color-coded by
   confidence), plus a downloadable `.xlsx` with flagged rows highlighted
   (red = High, yellow = Medium) and a "Business Context" column added.

## Architecture

The UI is plain HTML/CSS/JS (`static/index.html`, `static/style.css`,
`static/app.js`) — no Python involved in rendering it, so every element is
styled exactly as written. A small Flask backend (`server.py`) serves that
page and exposes the detection engine (`anomaly_engine.py`) as a JSON API
that the page's JavaScript calls with `fetch()`. `anomaly_engine.py` itself
has no web-framework dependency at all — plain pandas/scikit-learn/openpyxl,
reusable and unit-testable on its own, independent of whatever sits in front
of it.

## Setup

**1. Install Python dependencies** (Python 3.9+ recommended):
```bash
pip install -r requirements.txt
```

**2. (Optional but recommended) Install Ollama** for the AI-generated notes:
- Download it from [ollama.com/download](https://ollama.com/download) and install.
- Pull a model, e.g.:
  ```bash
  ollama pull llama3.1
  ```
  (Any chat-capable model works — `mistral`, `phi3`, `qwen2.5`, etc. Just make
  sure the name matches what you enter in the app's sidebar.)
- Ollama runs its own local server automatically after install (usually at
  `http://localhost:11434`) — nothing else to start.
- Don't want to use Ollama at all? Flip off "Use local Ollama model" in the
  sidebar — you'll get the offline template notes instead, fully functional,
  just less conversational.

**3. Run the app:**
```bash
python server.py
```
This starts a local server and opens `http://127.0.0.1:5000` in your browser
automatically. Leave the terminal window open while you use it. To run it
again later, just repeat this command — that's the "trigger."

## Try it immediately

Upload the included `sample_data.xlsx` — synthetic expense data with 14
seeded anomalies, some inside an "Executive Travel" department. In the
sidebar, set the high-risk column to `Department` and mark `Executive
Travel` and `Finance` as high-risk to see the confidence boost in action.

Want a bigger or different sample? Edit and re-run:
```bash
python generate_sample_data.py
```

## Files

| File | Purpose |
|---|---|
| `server.py` | Flask backend — serves the UI and exposes `/api/*` endpoints |
| `anomaly_engine.py` | All detection/scoring/notes/export logic (framework-agnostic — reusable, testable) |
| `static/index.html` | Page markup |
| `static/style.css` | All styling — dark theme, colored confidence badges, custom-built controls |
| `static/app.js` | All interactivity — upload, config, run detection, render results |
| `config.yaml` | Persisted settings: high-risk categories, Ollama model, detection thresholds |
| `generate_sample_data.py` | Builds `sample_data.xlsx` for a quick test drive |
| `requirements.txt` | Python dependencies |

## Customizing

- **Thresholds** (Z-score cutoff, IQR multiplier, expected anomaly %) are
  adjustable live in the sidebar in Manual mode, and saved to `config.yaml`
  when you click "Save settings."
- **Multiple high-risk columns**: the current design supports one column at a
  time (kept simple on purpose). If you need more, the easiest extension is
  to add a second `high_risk_2` block in `config.yaml` and mirror the logic
  in `combine_results()` inside `anomaly_engine.py`.
- **Swap the LLM**: `ollama_note()` in `anomaly_engine.py` is a single
  function hitting Ollama's REST API — point it at a different local server
  or model without touching the rest of the app.
- **Colors/fonts**: all in `static/style.css`, under the `:root { ... }`
  block at the top — change the hex values there to re-theme everything at
  once.
